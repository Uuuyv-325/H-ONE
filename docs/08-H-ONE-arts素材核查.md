## 3. 接入前需要处理的具体问题

1. **素材表不是已经定义好的规则网格。** `stand_walk_sprite.png` 的大主体分两行，各约四个；`turn-into-star-sprite.png` 的大主体分两行，各约五个，且变化中的主体尺寸不同。主块外还有小型不透明区域；降低 Alpha 阈值后，一些相邻区域会被淡像素连在一起。不能按“每个连通块一个 Sprite”或未经确认的等分网格直接批量导入。先补左上角原点的裁切矩形、状态、帧序和留边表，再换算 Unity 坐标；低阈值像素是否属于光效也需明确。
2. **动作帧需稳定的画布与脚底基线。** PNG 表内主体约数百像素高，并非现已交付的 256×256 单帧包；GIF 虽有统一 480² 画布，但行走帧非透明包围盒底边为 446–449 px，不能将各帧各自裁紧、居中后视为脚底已对齐。包围盒变化本身也不能证明脚滑。需人工指定真实脚底、pivot、镜像规则及整体比例，在 Game view 验证；本轮没有缩放、补画布或修改原像素。
3. **变星演示不能阻塞发射。** 美术基线 CH-06 的可见过渡约 0.15–0.2 s，实际发射由松 E 成功触发；GIF 为 1.76 s 无限循环。试装时应配置单次表现、调整帧选择/播放率或让过渡与运动重叠，并测试可读性，不能等 GIF 播完才发射。不能仅压缩到很短时长就宣称动作质量通过。
4. **优先从透明 PNG 整理，GIF 用于参考。** 三张表保留半透明边缘；GIF 每帧可见颜色约 123–233 种，透明度为二值，可能丢失源图边缘层次。GIF 的帧时长/循环设置也不会自动成为项目中已配置好的 Sprite 动画，仍需显式设置 AnimationClip 与状态驱动。
5. **比例与纹理导入要在 P0 验证。** PNG 的约 300 DPI 不决定 Unity 世界大小，PPU/实际显示高度才决定。原图应保留源分辨率，不能因为现有占位是 128 PPU 就直接套同样显示大小或盲目重采样。若整张导入，需检查 Max Size 是否缩小到 2048；若以未压缩 RGBA32 保留整张 4K，每张基础像素约 31.64 MiB，四张约 126.56 MiB，均未计 mipmap/额外副本。这是像素量估算，不是当前 Unity 实测内存；按裁切后实际用途选择尺寸/压缩。
6. **机关状态与交互语义还没有交接表。** 尚无空/激活/当前星台、压板抬起/压下、每片对应哪关/哪个 ID 等映射。仅有文件名不能确认这些状态齐全，也不能确认发光层是否独立、压力板形变是否匹配碰撞、六片星图是否足量。目录中没有可明确登记为三乐器、完整地形、桥/门、星槽/星影、图形 HUD/教学等的独立交付说明，完整首章需求仍未闭合。
7. **菜单整图不能替代 UI 组件。** 可先保留为静态页面候选；正式按钮、中文文本、焦点/悬停/按下/禁用态、重置与重开图标应独立接入已有 uGUI。如果原图含文字或控件，需人工确认可用区域或补分层交付；本轮没有识别图中文字，也不建议用生图方式移除内容。

## 4. 建议整理顺序与验收边界

先为 `stand_walk_sprite.png` 补待机/行走帧序、统一基线和一个实际角色尺寸样本；同时标注星台/压力板/碎片表的物件与状态，选一组作 P0 试装。之后处理变星 PNG 表，并以 GIF 核对作者预期时序；菜单图单独决定静态展示或补交组件。动作缺帧、透明层、帧序与物件状态均由补充说明或人工目视确认，不通过猜测填入。

后续可在 README 允许范围内，用本机程序按确认后的矩形裁切，输出到 H-ONE 的独立暂存/接入目录并保留来源与修订记录。保留原目录不动；裁切候选不覆盖 `Assets/Game/Art/P0` 共用图。实际资源导入时再遵循 WSL/Windows 同步、`.meta`/子 Sprite 引用保护和运行验收规则。

本轮没有完成风格板、完整源工程、正式 manifest 或 P0 Game view 验收；没有把候选来源登记成正式资源已交付/已接入/已验收。[替换 Checklist](06-占位美术替换Checklist.md) 中 ART/NEW 勾选状态保持不变。
