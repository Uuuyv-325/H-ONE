实施分支：`feat/chapter01-starshot`，起点 `7520c1a`。本次完成 M0/M1 的程序与灰盒运行门槛；P0 正式美术/音乐的整批验收仍未完成，不代表第一关已完成。原始策划 `.md` / `.docx` 未改写。

### 产出与使用

- 独立打开 `Assets/Game/Scenes/Chapter01_Core.unity` 即可 Play；这是核心试验场，不是 `Chapter01_01` 正式关卡。没有改发布构建列表。
- A/D 行走、Space 单跳；接地按住 E、鼠标瞄准、松 E 直线发射；右键取消；Esc 暂停/恢复。R 的 Action 已预留，召回要等 M2 有星影后实现。
- `PlayerTuning` / `LevelDefinition` 为配置资产；`LevelSession` 保存本次关卡会话中的唯一碎片 ID、最后接触并激活的星台。不会写入配置资产或磁盘存档。
- 人形 Dynamic 刚体与星弹 Kinematic 扫掠分别由小型 Motor 控制。预览与飞行共享 `StarPathSolver` 的半径、过滤、反射、skin 和预算；预览不修改游戏状态。
- 同一次发射共用一次反弹，第二次实体接触结束；薄墙、斜面、坑底危险区、时间/射程耗尽与越界均可检验。每步最多 8 次求解，初始重叠安全终止。
- F1 只由星弹收集，复合 Collider 与重复碰触不重复记数。人形碰触无效；普通失败后保留 F1，约 0.5 秒回最后激活星台，主出生点受阻时使用备用点。
- 蓄力取消、暂停、失焦与重组清除旧输入。按住 E 跨暂停后必须松开再按，飞行暂停后原位继续。重组重置相机跟踪历史。
- 七张原创技术 Sprite、七个原创合成 WAV，供灰盒反馈试装。AudioSource 接 `Core.mixer` 的 SFX 总线，Music 总线预留，`MusicVol` / `SFXVol` 可读取；声音不驱动玩法状态。
- `H-ONE/Validate Active Core Scene` 检查本场景玩家引用、稳定 ID、F1 配置与实体重叠。新建工具仅允许创建不存在的 Core 场景，拒绝覆盖已有场景。

### 验证结果

环境：Windows Editor `6000.0.84f1`，URP 2D，既有 `Rigidbody2D/Collider2D`，固定步长 0.02 秒。通过 Windows CLI 连接实际 Editor，未用 Linux 假编译代替运行。

| 检查 | 结果 / 边界 |
| --- | --- |
| EditMode | 16 / 16：稳定 ID、重复收集、1/6 cm 薄墙、斜面法线、一次预算、墙后片遮挡、同位危险优先、自身过滤、初始重叠、小房间居中及射程 |
| 预览与分步飞行 | 以 30/60/120 次分步查询同一静态世界，终点差 <0.01 unit；这是分步一致性检查，不是三个实际渲染帧率的设备基准 |
| 薄墙命中点 | 与解析几何差约 0.005 unit；测试容差 0.01 unit，严于方案的 0.1 unit 目标；未为消除查询容差改物理全局设置 |
| PlayMode | 8 / 8：真实 Input Actions 事件驱动走跳、空中禁蓄、取消/失焦/暂停松键、跨暂停持键、星弹直飞与冻结、人形不收片、失败保片、星台备用点、重组计时；连续发射后仍可蓄力、取消后循环音停止且声源数量不增长 |
| 跳高 | 实测位于 2.2 ± 0.08 unit；速度 4.4 unit/s；单跳，coyote / 输入缓冲各 0.1 秒 |
| 空场景射程 | 最短蓄力 10 unit，满蓄 18 unit；分别以 50 Hz Motor 推进测量，误差 <0.002 unit，飞行预算不会在反射时重置 |
| 重组 | 实测位于 0.50 ± 0.05 秒；暂停不消耗计时；重复失败不创建第二个玩家 |
| Game view | 已检查 1280×720、1920×1080 和 1280×800，确认画面非纯色、角色脚底对齐，预览可见；场景是灰盒，不作为正式美术验收 |
| 现场帧推进 | Play Mode 连续读取 frameCount 确实增长；单相机、单 AudioListener；测试产生的临时设置与虚拟设备在结束时恢复/清理 |
| Console | 最终运行无新玩法错误、无编译错误；AI Assistant Account API 网络/焦点警告为现有环境问题，不作为玩法失败 |

回归中修复：暂停跨越持键导致下一次蓄力无法开始；虚拟设备筛选后未重新绑定导致测试输入无效；角色自动裁切 Sprite 后脚底错位。最后一项通过 Visual 子节点对齐解决，保留现有 Sprite 引用；当前 Sprite 包不提供技能模板的新能力接口，没有绕过检查修改 Sprite 元数据。
