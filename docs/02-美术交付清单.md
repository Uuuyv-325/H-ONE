日期：2026-11-04。对应[架构与规则基线](01-整体架构与落地路线.md)。本清单覆盖第一章两关；第二、三章不下单。数量是制作估算单位，变体、状态与动画帧不能全部按独立设计重复计费。

## 1. 视觉方向与首轮样板

**原案确定**：古希腊神庙、星座精灵、金色星光、暗蓝遗迹、陶土红/黑绘点缀；通过壁画、地贴、机关外形、幽灵示范表达玩法。

**本次风格建议**：高清二维绘本/剪纸式横版，轮廓简洁，少量陶土颗粒与马赛克质感，柔和色块塑形。侧视玩法层保持清楚的水平站立面；背景可有轻微透视，不能把透视装饰画成可走平台。角色约 2.5–3 头身，小披风和月桂星环形成识别轮廓。不按像素画规格制作，也不需要三维模型。

光源叙事：冷月光照入暗蓝神庙，角色和可互动星纹发出暖金光；陶土红集中在器物和壁画。背景细节、对比和饱和度低于可玩层；不要让整座神庙同亮度发光。

| 色彩角色 | 样板 HEX | 用途 |
| --- | --- | --- |
| 最深背景 | `#111A33` | 深空、远景间隙，保留蓝相 |
| 神庙暗面 | `#253859` | 远中景石块、结构阴影 |
| 石材中间色 | `#65778A` | 地形与立柱，不做大面积高亮 |
| 月光浅色 | `#D9DFD9` | 可站立上沿、局部石面与角色浅色 |
| 陶土红 | `#B75D46` | 陶瓶、壁画底、脆陶墙 |
| 黑绘墨色 | `#29242D` | 陶器纹样与轮廓 |
| 星光金 | `#F3C969` | 玩家、交互线、进度与成功反馈 |

## 2. 通用制作与导出规范

### 2.1 尺寸、坐标和文件

- 参考画面 1920×1080，主宽高比 16:9；HUD 留边至少 48 px，并验 1280×720 与 16:10。世界画面不在图片中烘焙 HUD。
- 世界 Sprite 暂定 **128 PPU**：1 unit 对应 128 源像素；主网格 1 unit，辅助网格 0.25 unit（32 px）。参考镜头高约 10.8 unit，角色可见高约 1.6 unit，1080p 中约 160 px。镜头和 PPU 在 P0 一起定版。
- 角色帧画布统一 256×256，脚底基线固定；可见人形约 205 px 高。披风/头冠预留透明空间，不为填满画布拉伸角色。
- 一般机关单块不超过 1024×1024，常用 256/512；重复地块 128×128 或其倍数。大门、背景按分层/分段拆，不交一张超宽完整关卡大图。
- 游戏导出透明 PNG，RGBA、sRGB，直通 Alpha；保留透明边缘颜色，不在黑/白底上预合成。软光单独一层/文件；不把 bloom、屏幕震动或相机模糊烘焙到主体。
- 可编辑源文件 PSD/PSB、KRA、CLIP 或实际工具工程，图层分组清楚；矢量图标同时交 SVG 源与 PNG。字体、笔刷和外部纹理附名称、授权/来源说明。
- 序列帧按 `_000` 开始连续编号、固定画布与 pivot，默认先交独立帧，打图集由 Unity 导入流程处理。若交 sprite sheet，必须交行列、单格尺寸、留边与帧序表，禁止每帧自动裁切导致抖动。
- 角色 pivot 在脚底基线，球状星弹在中心；地面/平台用顶面中点或统一拼接原点；旋转/反弹乐器另标实际碰撞面。具体归一化 pivot 写入清单，不只口头说明。
- 文件名 ASCII：`ch01_<category>_<asset>_<state>_v01.png`；帧用 `..._idle_000.png`；最终稳定文件路径不随返修改名，版本写在外部交付包与 manifest 中。中文说明保存在清单。
- 源文件交付目录与游戏导出目录分开，巨型工作文件不默认放进 Unity `Assets`。新 Unity 资源的 `.meta` 由项目侧生成并保存，返修保留 GUID，不替换成随机新资源。

### 2.2 动画、材质和职责

首章采用 Sprite 序列帧 + 少量 Transform/Shader 动效，不依赖付费骨骼动画插件。普通角色动画按 12 fps 起制，快反馈可用 18–24 fps 或引擎插值；表中秒数是游戏可见时长，导入时可调整播放率。

身体、披风可以在源文件中分层，但首批导出合成帧。金光、星环、尾迹、召回线单独导出，便于改变强度。Sprite-Lit/Unlit 的最终分配由技术接入：背景可 Unlit，主要实体适度受 2D Light 影响，发光层单独叠加；默认不要求法线贴图。

美术交形状与运动意图，程序负责轨迹线、反弹几何、碎片收集判定、桥碰撞、鼓波半径、失败时序。任何 Animator event 都不能成为机关生效的唯一依据。附一份动效预览视频/动图，但预览不能代替序列帧和参数。

### 2.3 视觉语义

| 类别 | 必须出现的形态信息 | 不要造成的误解 |
| --- | --- | --- |
| 普通实体墙 | 连续实边、清楚碰撞轮廓，低发光 | “无光”表示无特殊交互，不代表星弹可穿墙；仍遵循普通反弹规则 |
| 特殊可撞物 | 星纹/金边脉动 + 对应物件轮廓 | 不可仅靠换色说明撞击作用 |
| 可站立面 | 连续上沿和有厚度的承重结构 | 背景残垣不能画同等亮度和完整可站立边 |
| 持续压板 | 压下高度 + 占用亮纹，移走恢复 | 不和一次性开关使用同一个锁定勾形 |
| 锁存开关 | 星纹由空心变实心/连线闭合 | 成功后不能看上去还在等待输入 |
| 星影 | 中空身体、半透明边缘、静态月桂底座 | 不画成第二名玩家，不做行走与输入提示 |
| 连接关系 | 同形纹样 + 可追踪线路/镶嵌 | 两个目标即使都为金色也能按纹样匹配 |

## 8. 批次、交付结构与验收

### 分批顺序

1. **P0 风格与玩法样板**：AD 全部、角色待机/行走样片、最小地形、里拉/槽/碎片、基础星光。交一屏实际可导入素材；确认轮廓、128 PPU、角色比例、深浅层级和三种形态区别。
2. **P1 第一关完整闭环**：除推石外的角色状态、共享环境第一版、第一关机关与全部反馈、TUT-01–04、基础 HUD/菜单。实际玩通后修正轨迹/地贴/镜头边界，再锁公共套件。
3. **P2 第二关与整体收尾**：推石、压板/桥、手鼓/陶墙、排箫/平台、S1/S2、第二关门/碎片/壁画、环境变体与标题。与第二关音频一起做可读性和时长验收。

每批交付包：

```text
ArtDelivery/ch01_p1_v001/
  Source/                 # 分层源文件，不直接导入 Unity
  Export/{Characters,Environment,Mechanisms,UI,VFX,Tutorial}/
  Preview/                # 透明棋盘/深色背景预览，动画演示
  manifest.csv
  palette.png
  palette.txt
  changes.md
  licenses.md
```

`manifest.csv` 必填：`asset_id, file, category, batch, width_px, height_px, ppu, pivot_x, pivot_y, state, frame_count, fps, loop, anchor_notes, collider_notes, source_file, revision`。纯 UI 的 ppu 可写 `n/a`，9-slice 边界和动画时长放 notes。所有返修改动写 `changes.md`，列明是否改过尺寸、pivot、帧数或连接点。

### 逐项验收

- 文件名与 manifest 对得上，源文件可打开、链接图层/字体齐全；无漏帧、透明黑边、越界裁切和版权来源缺失。
- 同一动画所有帧画布、脚底和 pivot 一致；左右镜像、上下平台拼接和地形拐角在实际比例下检查。
- 任意机关至少能读懂“可用、触发中、已完成/占用”；持续压板与锁存开关不同，星影与教学幽灵不同。
- 人形、星弹、星影在暗蓝背景上都清楚；普通石材、特殊机关和远景不争夺最高亮度。灰度检查与关闭 bloom 检查均通过。
- 轨迹、鼓波、平台顶面、琴弦反射面和关卡碰撞匹配；实际允许角度优先，不能为了漂亮把视觉法线画歪。
- 1920×1080 与 1280×720 检查 HUD、壁画和碎片轮廓；静音试玩仍能理解关键机制。
- 所有粒子效果有起始、持续和结束意图；循环不跳帧，叠加不白屏；大面积透明贴图和额外背景层先在目标机器测开销。
