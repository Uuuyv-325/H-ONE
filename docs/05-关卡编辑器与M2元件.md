# M2 元件与关卡编辑器

本工具按 2026-11-04 的明确追加要求在 M2 制作，服务首章的 Scene / Prefab 创作。沿用 Unity 6000.0.84f1、URP 2D、Rigidbody2D / Collider2D；不依赖额外包，不改写旧 Northline，原版工具不修改发布构建列表（11-10 的独立 M2ReleaseAuthoring 另管理 MainMenu/Gallery 发布入口）。当前元件覆盖 M2 星影闭环和持续机关组合；里拉、鼓波、脆墙、锁存开关、排箫与出口条件仍在 M3/M4。

## 1. 开始使用

1. 默认打开 `Assets/Game/Scenes/MainMenu.unity`，进入新机关试场；历史 `Chapter01_ShadowSlice.unity` 仍可直接调试。若需从当前场景 Play 或跑 PlayMode 测试，先用 `H-ONE/Play From Active Scene (debug and tests)` 清除 Editor 入口覆盖；批处理 CI 不设置入口覆盖。以下历史样例路线仍适用。它是可重复测试的 M2 样例，不是完整第一关。
2. 站在入口星台，按住 E 并用鼠标瞄准近处暗星纹岩石槽，松 E 留影；入槽后星纹点亮，本体约 0.5 秒回星台。A/D + Space 跳上金色承重面，再按 E 发射可拿上方碎片。
3. R 开始 1 秒召回；结束前平台和压板仍然有效。再向高处压板槽发射，形成右侧桥；走过桥可激活另一侧星台。站在桥上撤影可能坠落，但会回最后的安全星台，仍可重新架桥。
4. Esc 打开 uGUI 暂停菜单：`Resume` 恢复、`Reset puzzle` 只重置当前星台关联组并保留碎片、`Restart level` 清空本关碎片并回入口。普通失败保留星影；不会把压板或桥永久点亮。

操作使用 `ChapterPlayer.inputactions`。召回计时由关卡的 `ShadowService` 持有，独立于玩家重组；暂停冻结游戏时间，重复 R 不排队。成功入槽和失败反馈分开。

2026-11-10 星槽外观更新：PlatformSocket / PlateSocket 的 `Visual` 使用 Delivery01 `rock_dark`（空）/ `rock_light`（占槽），1 秒召回结束后恢复暗图。`StarSocketArtView` 只读实际占用；星影核心和承重条独立保留，锁定降亮度仍是临时提示，不能替代尚缺的 TUT-03/04 / 锁形教学。`DeliveredArtAuthoring` 同时处理现有槽和 `LevelPieceFactory` 新建默认，运行编辑目录复用已更新 Prefab，不覆盖共用 P0 `empty_node` 的收片节点用途。

### 游戏内编辑

仅在 Unity Editor / Development Build 中，在样例或新试场运行时点右上角 `Edit level` 进入编辑模式。左侧选择 `Select / move` 后可拖动元件；选调色板元件后在场景中点击放置。选择方格为 0.25 或 1 unit，滚轮缩放视图、中键拖动画布。底栏可设置实体尺寸、将选中星台设为入口或删除选中元件。选桥/门后点 `Link signal`，再点压力板或压板型星槽即可连线；`Puzzle group` 选择创建后续元件所属谜题组。

`Save` 将关卡写入 `Application.persistentDataPath/Levels/<名称>.json`；顶部列表选择后点 `Load` 可反序列化并重建元件、稳定 ID、尺寸、分组、入口和机关引用。`New` 创建带地面和入口星台的空白布局。`Play test` 先保存并从入口开始试玩；试玩时右上角按钮变为 `Stop test`，点击后恢复试玩前的已保存布局并回到编辑。`Return` 关闭编辑器、更新碎片声明/组注册、恢复相机编辑前缩放并恢复运行；不承诺回放编辑前的玩家状态/进度快照。

JSON 文件使用版本号 `1`，保存关卡元件数据，不保存玩家进度或应用设置。未知版本、重复元件/碎片/星台 ID、缺失 Prefab、无入口星台和无效机关连线会在加载前拒绝，避免损坏当前布局。

## 2. Unity Editor 元件摆放工具

菜单 **H-ONE → Chapter Level Editor** 打开 UI Toolkit 窗口。

1. 点 `Create new level…`，选 `Assets/Game/Scenes` 内的新文件名。按 Unity 提示先处理未保存场景。工具创建独立 LevelDefinition、入口星台、玩家、相机、轨迹、暂停菜单和基础地形。拒绝覆盖已有 Scene；没有删除原型根节点的操作。
2. `Parent` 选择所属 Transform；`Piece` 选择元件；`Grid` 用 1 或 0.25。填写坐标点 `Place piece`，或打开 Scene 视图左键放置。Alt 继续导航；Esc 退出放置。普通 Move/Rotate 工具继续有效。
3. 要分谜题时点 `Create puzzle group`，在该组下摆放可复位对象。选择星台，指定 `Puzzle group` 后点 `Assign selected dais to group`。每个星台必须有组；入口默认关联 Puzzle_A。
4. 桥/门的 `Signal source` 指向 PressurePlate，`Bridge / gate` 指向 SignalBarrier，点 `Connect source → bridge / gate`。Scene 视图显示点线。PlateSocket 的压力板在其子物体上，不是空环根组件。
5. 点 `Gather group's reset targets`。组按“复位物理体 → 同步物理查询 → 重算压力板 → 重算桥/门”执行；新加可复位物体后应重新收集。不要把别组对象塞进同一复位数组。
6. 选中地块、桥、门或石块，用 `Box / Visual size` + Resize 同时改碰撞和外观；保持根 scale 为 1。星槽承重面由 ShadowPlatform 的 BoxCollider2D 单独定义。
7. 用 `Duplicate selected with fresh IDs` 复制元件/组。它为复制品分配新稳定 ID，并把新组注册到会话。Unity 自带 Ctrl+D 会复制 ID，校验器会报重复；不要忽略。
8. `Validate active level` 列出可点击定位的问题，再 `Save active scene`。增删碎片后可用 `Sync fragment declarations from scene` 同步配置中的 ID 集合；它不改已有碎片 ID。正常 Unity Undo/Redo 可撤回摆放、连线、尺寸、复制和配置修改。

选择 Inspector 显示完整序列化参数；视觉替换、Collider 编辑、Camera Bounds 和玩家配置可直接调整。编辑器不自动推算谜题可解性，不替代人工试玩。保存重载后仍须运行新场景验证。

## 3. 可复用元件

资产位于 `Assets/Game/Prefabs/Mechanisms/`，通过编辑器放置时自动绑定当前 LevelSession，并生成新 ID；直接拖 Prefab 时需手工绑定场景依赖和 ID。

| Prefab | 运行职责 / 配置 |
| --- | --- |
| Solid | 实体碰撞与独立 Visual；普通墙共享一次反弹预算 |
| Hazard | Trigger 通知失败；同距离危险优先于入槽 |
| Checkpoint | 安全主/备用出生点、稳定 ID、所属 PuzzleGroup |
| Fragment | 只由星弹收集，ID 必须在 LevelDefinition 声明；失败保留，重开重现 |
| PlatformSocket | 空槽捕获区 + 独立 ShadowPlatform；星影有 2 unit 宽实体承重面 |
| PlateSocket | 空槽 + 本地压力板 + 压板型星影；实体重叠产生占用，无远程暗线 |
| PressurePlate | 只接受带 PressureWeight 的有效占用者，按稳定 ID 去重；人形/飞行星弹不计重 |
| Bridge | BoolSignal true 时形成，false 时撤去，约 0.2 秒过渡；不锁存 |
| Gate | BoolSignal true 时打开；关闭区域有人/重物时等待净空，信号状态与实体状态分开 |
| Stone | Dynamic 重物基础件、锁旋转、可复位；供占用与组合试验，尚未包含 M4 的完整受控侧推/坑边防困规则 |

`Create missing piece prefabs` 只补缺失资产，不重写已有作者改动。样例创建菜单同样仅创建不存在的新文件。Prefab 的场景依赖为空是有意设计；绑定发生于摆放时，不把某关卡引用写入共享 Prefab。

## 4. 脚本接口与生命周期

- `LevelSession`：会话唯一碎片集合，`ResetCurrentPuzzle(player)` / `RestartLevel(player)`；重置先检查安全星台并转移玩家，无法安全转移则返回 false，保持原状态。
- `ShadowService`：`TryPlace`、`BeginRecall`、`Clear`；`Changed / RecallStarted / Recalled` 是已完成状态的表现入口。一个关卡一个服务、一个占用槽；槽禁用、服务禁用、卸载时清理。
- `StarSocket`：稳定 ID、服务、ShadowPlatform 显式引用。空槽在共享 StarPathSolver 中预测终止；已占额度的槽按普通实体反射/终止。预测不实例化、显隐、收集或播放声音。
- `PressureWeight`：Stone / Shadow 类型与稳定 ID；禁止给玩家或飞行查询体挂此标记。多个 Collider 同属一个 ID，只计一份重量。
- `BoolSignal`：只读 Value 和边沿 Changed；PressurePlate 每固定步从实际重叠重算，失活对象不会留下回调残留。
- `SignalBarrier`：`solidWhenTrue` 区分桥与门。物理生效与可见过渡中点一致；形成实体前检查玩家/重物，避免凭空穿体，门不会挤飞石块。
- `PuzzleGroup`：序列化稳定 ID 与明确 resetTargets。后续组件实现 `IPuzzleResettable`；持久碎片、将来的锁存开关/碎墙不属于普通谜题复位目标。
- `ResettableBody2D`：在 Awake 记初始姿态，动态 Apply/拖动作者摆位后通过 CaptureInitialPose 更新复位基准，复位清速度。没有跨应用存档，不把 mutable 状态写进 ScriptableObject。
- `ShadowFeedback / PuzzlePauseMenu`：分别负责表现和 uGUI 操作入口；音频/动画完成不控制入槽、召回、碰撞或重组时间。

固定顺序为 ShadowService(-100) → PressurePlate(-90) → SignalBarrier(-80) → Player(0)，之后 Unity 执行物理模拟；复位另显式同步并重算。仅人形 Motor / 星弹 Motor 中当前激活者拥有玩家运动。

## 5. 验证与边界

校验覆盖玩家依赖、稳定 ID、跨场景引用、碎片配置/实体重叠、槽危险重叠、复位组注册/缺项、槽平台/重量、压板 Trigger、桥门信号。它会报告配置问题，不自动删除场景物体或重写 ID。

EditMode 覆盖共享查询、已有槽反射、危险优先、遮挡、Prefab ID，以及新关卡创建→摆放→连线→保存→重载。PlayMode 覆盖实际 Input Actions、踩影再发射、1 秒召回、暂停/失败/复位、占用去重、安全关门、撤桥恢复与卸载。完整运行记录见[开发进度](04-开发进度.md)。

当前使用既有 P0 技术图/音做组合和事件反馈，正式 CH-08/CH-10、ME 槽/桥与 TUT-03/04 等素材仍待验收。样例中的星形、顶面和演示剪影只是技术占位；不代表正式美术、教学可读性或音频听感已通过。尚未制作 M3 的完整 A–D 首关、M4 乐器组合和 M5 首章完整发布；11-10 试场构建只验证 M2 入口与机制陈列，见 [M2 收尾](10-M2收尾与机关试场.md)。
